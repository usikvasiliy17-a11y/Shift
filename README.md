# SHIFT — умный планировщик жизни

Полноценный веб-апп в одной папке, без шага сборки (npm/vite не нужны).
React загружается прямо в браузере пользователя с CDN, поэтому на GitHub
достаточно просто разместить файлы как есть.

## Файлы в этой папке

- `index.html` — всё приложение (интерфейс, вся логика, стили)
- `manifest.json` — чтобы приложение можно было установить на телефон
- `service-worker.js` — кэширует приложение для работы при слабом/пропавшем интернете
- `icon-192.png`, `icon-512.png`, `icon-180.png`, `favicon-32.png` — иконки

## Как опубликовать на GitHub Pages

1. Создай новый репозиторий на GitHub, например `shift-app`.
2. Загрузи в него **все файлы этой папки** одним выделением — через
   "Add file → Upload files", перетащи все файлы сразу (папок внутри
   нет, всё лежит в корне, так что ничего вкладывать не нужно).
3. Зайди в Settings → Pages.
4. В "Build and deployment" выбери Source: "Deploy from a branch",
   Branch: `main`, папка `/ (root)`. Сохрани.
5. Через 1–2 минуты сайт будет доступен по адресу:
   `https://<твой-логин>.github.io/shift-app/`

## Проверка перед публикацией

Просто открой `index.html` двойным кликом — приложение запустится
в браузере (нужен интернет при первом запуске).

## Установка на телефон

Открой опубликованную ссылку на телефоне:
- **iPhone (Safari):** «Поделиться» → «На экран Домой».
- **Android (Chrome):** меню (⋮) → «Добавить на главный экран» —
  Chrome обычно сам предложит установку, т.к. манифест настроен.

Иконка и запуск будут выглядеть как у обычного приложения, без
адресной строки браузера.

## Как это работает без сборки

`index.html` подключает React и React DOM как ES-модули с CDN
(esm.sh) через `<script type="importmap">`, а JSX-код приложения
компилируется прямо в браузере с помощью Babel Standalone. Это
избавляет от Node.js/npm/сборщика — весь проект состоит из
статических файлов, которые GitHub Pages отдаёт как есть.

Плюс: ничего не нужно устанавливать и собирать.
Минус: при *самом первом* открытии страницы нужен интернет, чтобы
подгрузить React/Babel; `service-worker.js` кэширует их после первого
визита, так что дальше приложение открывается заметно быстрее и
переживает нестабильную сеть — но это не полноценный офлайн-режим
уровня нативного приложения.

## Данные

Все события хранятся в `localStorage` браузера — то есть локально на
устройстве пользователя. Между разными браузерами и телефонами данные
не синхронизируются (это не нужно облачное хранилище, всё работает
без сервера).

## Если нужен настоящий build (Vite)

Если позже понадобится офлайн-режим без всяких оговорок, более
быстрая загрузка или сборка с оптимизацией — этот же код приложения
(`index.html`, секция между `<script type="text/babel">` и
`</script>`) один в один переносится в `src/App.jsx` обычного
Vite-проекта: `npm create vite@latest -- --template react`, вставить
код, `npm install lucide-react`, `npm run build`.
